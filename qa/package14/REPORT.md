Проверено в реальном Chromium/Edge:

- Все 30 записей открываются с правильным набором локальных фото; все 58 основных изображений и 58 миниатюр валидны.
- При 320, 390, 768 и 1440 px нет горизонтального переполнения документа и обоих диалогов.
- Увеличение упаковки, переходы по фото стрелками, возврат фокуса и замкнутый Tab работают.
- Первый Escape закрывает фото и возвращает фокус к миниатюре; второй закрывает упаковку. Стрелки в фото не меняют упаковку.
- Fallback не выдаёт фото вдохновения за выбранную модель. Ошибок JavaScript нет.
- `node --check tights-guide/packaging.js`, AST Python и офлайн-проверка всех 58 хешей проходят.
- `refresh-package-looks.py --refresh --limit 2` повторно скачал два снимка: оба хеша неизменны, публикация не изменена.

Артефакты: `browser-report.json`, `looks-{320,390,768,1440}.png`, `photo-{320,390,768,1440}.png`, `fallback-desktop.png`. При снимках экрана ожидается завершение `HTMLImageElement.decode()`, чтобы асинхронное декодирование WebP не давало ложные пустые превью.

## Обновление

`scripts/refresh-package-looks.py` по умолчанию проверяет файлы и привязки офлайн. `--refresh` загружает только явный allowlist URL уже просмотренных фото и сравнивает воспроизводимый WebP-хеш. Неизменные файлы не перезаписываются. Изменившееся содержимое помещается в `.cache/package-looks-review/` для просмотра; сайт не обновляется автоматически. `--restore-missing` может восстановить только файл с полностью совпадающим ожидаемым хешем. Поиск новых моделей и автоматическое утверждение непроверенных снимков не выполняются.

TLS-проверки не отключались. Недоступные из-за истёкших сертификатов источники пропущены; для Wolford и Trasparenze найдены доступные отдельные источники с точной моделью. Свободная лицензия на каталожные фото не заявлена.
