# ТОНКО: автоматическая лента и образы

Пользователь запросил фотографии по семи присланным примерам и новости на главной с автоматическим обновлением. Выбран в чате режим GitHub Pages с проверкой каждые 15 минут; задержки GitHub и источников объяснены.

## Решение

Существующий Python + HTML/CSS/JS сохраняется. Общий workflow публикации получает расписание `7,22,37,52 * * * *`. Сборщик читает публичные RSS/Atom из фиксированного списка, фильтрует тему, сохраняет только заголовок, источник, дату и ссылку. HTML источников и произвольные URL не выполняются и не вставляются в страницу. Предыдущая опубликованная лента используется при сбое; время успешной проверки не подменяется. Лента показывает возраст данных и частичную недоступность источников.

Главная получает новостной блок сразу после обложки и быстрых переходов. Заголовки на языке оригинала, EN/RU видимы. Полные статьи и внешние фотографии автоматически не копируются. Страница опрашивает собственный JSON раз в минуту, только пока видима. Новые записи предлагаются кнопкой, чтобы не сдвигать читаемый список. Новости также доступны в статическом HTML без JS.

Семь предоставленных изображений копируются в проект без ретуши, получают подписи без выдуманного авторства, адаптивные размеры и категорию образов. Мужские кадры также доступны в мужском фильтре. Низкое исходное разрешение не увеличивается искусственно. Главная показывает небольшой ряд образов, полный набор доступен в галерее.

## Рассмотренные варианты

1. GitHub Actions каждые 15 минут: выбран пользователем; без нового хостинга, задержки возможны.
2. Отдельный сборщик с проверкой 1–2 минуты: не выбран; нужна новая инфраструктура, мгновенность источников всё равно не гарантируется.

## Проверка

RSS/Atom, даты и будущие записи, тематический фильтр, дедупликация, опасные URL/HTML, частичный и полный сбой. Проверка реальных фидов, статических ссылок и JS. Осмотр главной и галереи на узком экране, идемпотентная сборка. После публикации — workflow и публичный JSON. Расписание GitHub в неактивных публичных репозиториях может отключиться спустя 60 дней: документировать, не обещать бессрочную работу без контроля.
