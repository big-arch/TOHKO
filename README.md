# ТОНКО

Независимая русскоязычная энциклопедия колготок, легинсов, капрона и чулочной индустрии.

Сайт: **https://big-arch.github.io/TOHKO/**

## Локальный запуск

Из корня репозитория:

```sh
python -m http.server 4185 --directory tights-guide
```

Открыть http://localhost:4185/. Сервер нужен для загрузки реестра логотипов. Сборка и установка npm-пакетов не требуются.

## Структура

- `tights-guide/` — публикуемый сайт, 35 HTML-файлов, стили и JavaScript.
- `tights-guide/data/brands.js` — исходный каталог 43 марок и моделей.
- `tights-guide/data/brand-research.js` — уточнения историй и источники; статус проверки отделён от наличия товаров.
- `tights-guide/data/photos.js` — фотографии галереи, авторы, лицензии.
- `tights-guide/data/logo-sources.json` — происхождение 20 оригинальных логотипов.
- `PRODUCT.md`, `DESIGN.md` — согласованное направление продукта и оформления.
- `reports/ТОНКО — аудит и первый выпуск.md` — оценка, изменения, ограничения и предложения.
- `scripts/story_content.py` — шесть оригинальных статей и девять событий архивной хронологии с первоисточниками.
- `tights-guide/experience.js`, `experience.css` — журнал, чтение, интерактивная история, увеличение фотографий и умеренные анимации.
- `reports/ТОНКО — журнал и интерактивный архив.md` — разбор десяти сайтов и результат третьего выпуска.

## Обновление редакционных страниц

Сайт раздаётся как готовые статические файлы. При изменении шаблонов или контента запускайте стадии по порядку:

```sh
python scripts/build-editorial.py
python scripts/build-experience.py
python scripts/build-videos.py
python scripts/build-packaging.py
python scripts/build-home-news.py
python scripts/optimize-images.py
python scripts/check-site.py
```

Первая стадия собирает основные тематические страницы. Вторая создаёт журнал, статьи и мастерскую. Третья собирает видеотеку, обновляет общую навигацию и добавляет связанные материалы. Изображения хранятся локально; их исходные адреса и подписи находятся в `data/editorial-media.json`. Повторная сборка не дублирует разделы.

Видеотека хранится в `tights-guide/data/videos.json`: YouTube ID, русское и исходное название, канал, темы, язык, ссылка и дата проверки. Проверяйте новые ролики и возможность их публикации перед добавлением. `build-videos.py` создаёт HTML и индекс `data/videos.js` для поиска. Ссылки доступны без JavaScript; плеер подключается только по нажатию. Избранные видео сохраняются только в браузере.

Основное действие в видеотеке — «Смотреть на сайте». Один встроенный проигрыватель выбранной платформы заменяет текущее видео при переключении; ссылки на канал и оригинал находятся в свёрнутом пункте «Источник». Официальный API загружается по первому нажатию и сообщает об ошибках. Если API недоступен, остаётся обычный iframe. Закрытие удаляет плеер, останавливает звук и отменяет отложенные действия. Проверки интеграции YouTube: `qa/check-inline-player.js` (Playwright, локальный сервер на порту 4185); результаты и пределы проверки — `qa/INLINE-PLAYER-QA.md`.

Выпуск 06 добавляет Vimeo: три фильма Swedish Stockings из серии Journey of a Thread идут первыми в видеотеке. `provider: "vimeo"` и числовой `providerId` задают второй плеер; для прежних записей используется YouTube. Фильтр «Без YouTube · Vimeo» и кнопка альтернативных видео после ошибки YouTube ведут к этим трём фильмам, а не к копиям прежних обзоров. SDK обеих платформ загружаются только после клика. Публичные ограничения YouTube не обходятся; все 11 обзоров сохранены с исходными ссылками. Проверка реального воспроизведения, фото и мобильной версии: `qa/check-media-v6.js` и `qa/MEDIA-V6-QA.md`.

С выпуска 05 мужской раздел посвящён одежде, сочетаниям и посадке. Статья 18+ снята с публикации; `fetish.html` оставлен как нейтральная страница с `noindex` для старых ссылок. Исключённые фотографии удалены из публикуемой папки, история Git не переписана.

Последняя стадия готовит адаптивные WebP-превью и добавляет `srcset`, `sizes` и приоритет обложек. Для неё нужен Pillow (`python -m pip install Pillow`). Готовые файлы включены в репозиторий, поэтому для просмотра и публикации Pillow не требуется. Оригиналы остаются в `assets/editorial`, варианты — в `assets/responsive`; просмотрщик и увеличение используют оригиналы.

## Проверка и публикация

```sh
python scripts/check-site.py
```

GitHub Actions проверяет локальные ссылки и синтаксис JavaScript, затем публикует только `tights-guide/` в GitHub Pages после push в `main`. Исследования и локальный кэш не входят в сайт. Workflow: `.github/workflows/pages.yml`.

Избранные модели, фотографии, статьи и место чтения хранятся в браузере конкретного устройства. Публичный сайт доступен с разных устройств; синхронизация подборок между ними не реализована.

## Автоматические новости и образы · выпуск 07

Главная содержит ленту публикаций и подборку из семи предоставленных владельцем фотографий. В галерее появился фильтр «Образы»; мужские фотографии также входят в фильтр «Мужчины». Исходники сохранены без ретуши, подписи не приписывают неизвестное авторство или бренд.

Новостной сборщик: `scripts/news_feed.py` и `scripts/update-news.py`. Источники заданы в `tights-guide/data/news-sources.json`: RSS/Atom брендов и модных изданий, а также Google News по ограниченному списку изданий. Публикуются заголовки на языке оригинала, короткие анонсы, даты и ссылки; для шести проверенных записей добавлены оригинальные разборы ТОНКО. Полные чужие статьи автоматически не копируются. При наличии явного изображения обложки в RSS reader может загрузить его с разрешённого домена источника. Это подборка из подключённых источников, не полный мониторинг интернета. Записи старше года, будущие даты, дубли и нетематические публикации исключаются. Тематический фильтр эвристический: его следует периодически проверять.

Workflow `.github/workflows/pages.yml` проверяет источники в минуты 7, 22, 37 и 52 каждого часа и публикует новый снимок на Pages. Ручной запуск доступен через Actions → Publish TONKO → Run workflow. Обновления не создают коммит каждые 15 минут: предыдущий снимок берётся с опубликованного сайта, результат сохраняется в артефакте Pages. При сбое источника старые записи сохраняются; при полном сбое время последнего успеха не меняется. На первой установке без данных и успешных источников workflow завершается ошибкой.

Открытая страница проверяет собственный `data/news.json` раз в минуту, пока вкладка видима. Новые заголовки появляются после нажатия «Показать новые публикации», чтобы список не сдвигался во время чтения. Кнопка «Проверить ленту» перечитывает опубликованный снимок, она не запускает обход внешних сайтов. При отсутствии JS показаны шесть заголовков из последней сборки.

GitHub может задерживать или пропускать запуски по расписанию. В публичном репозитории расписание автоматически отключается после 60 дней без активности репозитория; публикации артефактов не следует считать гарантией продления этого срока. Если время проверки на сайте устарело, проверьте Actions и включите workflow снова. Документация: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule

Локальное обновление (нужен curl с действующим хранилищем сертификатов):

```sh
python scripts/update-news.py
python scripts/build-home-news.py
python scripts/optimize-images.py
python -m unittest discover -s qa -p test_news.py
```

Для разработки без сети можно передать `--cache .cache`; этот режим не ставит отметку успешной сетевой проверки. Подключение новых изданий выполняется через фиксированный список источников. HTML из лент не вставляется в страницы, ссылки ограничены HTTPS и доменом источника; для Google News дополнительно проверяется издатель.

## Девятый выпуск · развёрнутые новости и архив упаковок

`packaging.html` — 501 изображение упаковок и фирменных вкладышей 25 брендов. Коллекция сгруппирована по производителям в алфавитном порядке: боковое оглавление на компьютере, раскрывающийся список на телефоне. В общем обзоре видны первые четыре изображения каждого бренда; «Показать ещё» раскрывает только его коллекцию. При выборе бренда показываются первые 36 изображений с продолжением. Без JavaScript доступен полный архив по брендам.

Сохраняются поиск по названию/вариантам, фильтр DEN, увеличение в два раза, клавиатурная навигация и прямые ссылки `?brand=…` и `?pack=…`. Источники, даты проверки и варианты хранятся в `data/packaging.json`. В выпуске 11 добавлены 115 проверенных изображений; шесть повторных видов объединены с существующими, 23 неподходящих кандидата исключены. Добавились бренды Elledue, Fiore, Gatta, Giulia, Giulietta и ORO. Каталожные характеристики DEN проверены по видимому обозначению упаковки, где в таблице продавца была ошибка. Изображения оптимизированы в WebP; архив не заявлен как полный мировой каталог.

Проверка группировки и просмотра: `python qa/check-packaging.py` (Playwright и Microsoft Edge). Без `TONKO_TEST_URL` скрипт сам запускает временный локальный HTTP-сервер; для публичного сайта можно задать `TONKO_TEST_URL=https://big-arch.github.io/TOHKO/`. Подробности: `qa/PACKAGING11-QA.md`.

Шесть свежих материалов имеют самостоятельный русский разбор (284–296 слов) с подзаголовками, проверенными источниками и отделёнными редакционными рекомендациями. Исходник — `data/news-digests.json`; `news_editorial.py` применяет его после каждого обновления, `news_render.py` собирает версию без JavaScript. Даты публикаций источников не заменяются временем обновления. Reader использует только иллюстрацию конкретной записи; общей случайной фотографии больше нет. При ошибке загрузки фото скрывается. В RSS принимаются только явно приложенные изображения из разрешённых доменов; HTML издателей не вставляется.

Новые новости поступают автоматически. При наличии GitHub Actions secret `OPENAI_API_KEY` дополнительные пересказы делает OpenAI; без ключа сохраняются короткие RSS-анонсы. RSS сам по себе не требует AI API. Ключи нельзя помещать в публикуемую папку или присылать в чат. Например, ключ OpenAI создаётся на https://platform.openai.com/api-keys; биллинг API отдельный от подписки ChatGPT.

В YouTube добавлены явные кнопки перехода на обычный youtube.com и обновления плеера после входа. Вход в отдельном окне не гарантирует доступ к cookies во встроенном iframe; состояние аккаунта и антибот-проверка остаются под управлением браузера и Google. ТОНКО не объявляет пользователя авторизованным и не получает его пароль. Без аккаунта остаётся HTML5-плеер Snag.

Проверка интерфейса: `qa/check-media9.py` (Playwright, Edge, локальный сервер 4185). `TONKO_TEST_URL` позволяет проверить опубликованную копию. Проверка YouTube выполняется с имитацией API и доказывает выбор хоста/сохранение режима, а не успешный вход в Google. Реальный медиапоток проверяется отдельно через `qa/check-media8-playback.py`.

## Автоматические пересказы OpenAI

1. В [Actions secrets репозитория](https://github.com/big-arch/TOHKO/settings/secrets/actions/new) добавить существующий ключ под именем `OPENAI_API_KEY`. Значение не передавать через чат и не сохранять в публикуемой папке. Новый ключ создавать не требуется.
2. После добавления сработает ближайший плановый запуск. Для немедленной проверки: Actions → Publish TONKO → Run workflow. Без секрета AI-стадия ничего не вызывает, обычная лента продолжает обновляться.
3. Отключение без удаления ключа: repository variable `OPENAI_NEWS_ENABLED=false`.

Модель — `gpt-6-luna`, Responses API со строгой JSON-схемой. Тексты извлекаются из открытых страниц прямых RSS-источников через Trafilatura 2.3.1. Google News не разворачивается автоматически; закрытые статьи, страницы с недостаточным текстом и невалидные ответы остаются анонсами. Модель не получает пароль/ключ и не выбирает URL или фотографию: используются только проверенные ссылки ленты и обложка этой публикации у издателя.

За запуск — максимум 3 API-запроса; за сутки UTC — 10 по сохранённому счётчику; вход ограничен 18 000 символов, выход — 4 000 токенов. Неудачные обращения тоже учитываются; повтор не ранее 24 часов, не более двух попыток для записи. Это ограничение обработки приложения, а не финансовый лимит аккаунта OpenAI. На проверенную дату тариф модели — $0.10 за миллион входных и $0.50 за миллион выходных токенов: [официальная карточка](https://developers.openai.com/api/docs/models/gpt-6-luna). Фактические расходы зависят от объёма текста и тарифа аккаунта.

Готовые результаты и счётчики сохраняются в Actions cache `.cache/news-ai-cache.json`, дополнительно пересказ входит в публичный снимок ленты. В кэше нет ключей и полных оригиналов. Кэш сохраняется до сборки/деплоя, чтобы ошибка публикации не заставляла заново оплачивать уже обработанный текст. Повреждённый кэш или ошибка его восстановления запрещают платные запросы; ошибка AI не мешает публикации RSS. Любая система кэширования может быть удалена/сброшена, поэтому для управления оплатой используйте также настройки своего API-проекта.

Автоматические тексты помечаются «AI-пересказ». Шесть ручных редакционных разборов имеют приоритет и не перезаписываются. Изменение даты публикации источника не подменяется датой генерации. Все обращения идут с сервера Actions, ключ в браузер не передаётся; `store=false`. Проверки: `python -m unittest discover -s qa -p 'test_news*.py'` и `qa/check-news-ai.py`. Детали — `qa/NEWS-AI-QA.md`.
