## Каталог моделей и цены

`catalog.html` показывает модели из разделов колготок и чулок «Лоретты», включая мужские и детские подразделы. На 17 ноября 2026 года проверены все 66 листингов (62 подраздела и 4 общих раздела): 1 565 моделей 83 брендов, из них 1 267 с текущей ценой. Повторы между категориями объединяются по товарному идентификатору. Фотографии моделей в каталоге и проверенные фотографии упаковок в архиве подписаны раздельно. Полные описания магазина и отзывы не перепечатываются.

Доступны выбор бренда и типа изделия, поиск, ценовые диапазоны и общая сортировка по возрастанию/убыванию цены. Неизвестная цена остаётся неизвестной. Рядом с рублёвой ценой показывается приблизительная сумма USD по официальному курсу Банка России с датой курса; это не курс оплаты заказа. Цены и наличие относятся к указанному продавцу и времени проверки.

Сборщик `scripts/collect-catalog18.py` сверяет полноту каждого подраздела со счётчиком источника. Отдельный процесс `catalog-refresh.yml` проверяет каталог ежедневно в 01:17 UTC (04:17 по Москве); GitHub может задерживать запуск. Он сохраняет полный снимок в репозитории для ближайшей плановой публикации, а сбой источника сохраняет предыдущие данные и их даты. Основной цикл новостей и видео только восстанавливает готовый каталог через `--restore-only`, поэтому длительный обход магазина его не задерживает. Через 48 часов без проверки интерфейс помечает цену как требующую обновления. Ошибка восстановления публичного снимка останавливает публикацию, чтобы старый репозиторный снимок не заменил более новые модели. Курс обновляется раз в московские сутки скриптом `scripts/update-exchange-rate.py`.

Для архива упаковок `scripts/build-catalog-links.py` связывает цену только по точной ссылке на товар либо точному сочетанию бренда, модели, типа и DEN. Неоднозначные совпадения пропускаются. У карточки сохраняются отдельные источники изображения и цены.

```sh
python scripts/collect-catalog18.py --deployed https://big-arch.github.io/TOHKO/
python scripts/update-exchange-rate.py --deployed
python scripts/build-catalog-links.py
python scripts/build-catalog.py
python scripts/build-packaging.py
python scripts/link-catalog.py
```

Для отдельного полного обхода используется `--refresh`, для продолжения скачивания изображений — `--resume`. Сырые страницы и HTTP-кэш не включаются в публикуемую папку. Подробности: [заметки сборщика](qa/catalog18-import/IMPORT-NOTES.md).

## Самостоятельное обновление сайта

Workflow [Publish TONKO](https://github.com/big-arch/TOHKO/actions/workflows/pages.yml) запускается после push в main, вручную и по расписанию в минуты 9, 24, 39 и 54 каждого часа. Он:

1. Проверяет код, загружает предыдущий опубликованный снимок и читает RSS/Atom восьми новостных источников и 31 источника видео.
2. Отбирает тематические публикации, убирает дубли и подтверждает прямую ссылку издателя, в том числе для обнаружений через Google News.
3. Сохраняет подготовленные пересказы. Генерация новых текстов через API в опубликованном workflow пока отключена по просьбе владельца приостановить работу над ИИ. Полные чужие статьи не перепечатываются; неподготовленные заголовки не выдаются за готовые статьи.
4. Публикует готовые материалы, сохраняет очередь и счётчики повторов. При временной ошибке предыдущие статьи остаются доступными.
5. Самостоятельно добавляет новые тематические видео из разрешённых каналов YouTube и журнала Swedish Stockings, проверяет официальную вставку и сохраняет локальное превью.
6. Пересобирает страницы и справочник помощника, затем публикует артефакт GitHub Pages. Редактор для обычного цикла обновления не нужен.

Главная проверяет собственный снимок раз в минуту, пока вкладка видна. Новые материалы предлагаются кнопкой «Показать новые публикации», чтобы список не прыгал во время чтения. «Проверить ленту» перечитывает опубликованный файл, а не запускает внешний обход.

Ограничения архива: до 200 готовых материалов и отдельно до 200 обнаружений в очереди. Поток новых неподготовленных заголовков не вытесняет готовые статьи. Внешние источники и расписание GitHub не гарантируют мгновенную публикацию. Плановый запуск может задерживаться; в публичном репозитории GitHub отключает расписание после 60 дней без активности репозитория. Чтобы сайт не зависел от ручных коммитов, отдельная задача после успешной публикации сохраняет снимок новостей, видео и новых превью в main, если в репозитории не было коммитов неделю. У неё отдельное право contents:write; ключ OpenAI ей недоступен. Push выполняется без force; при конкурирующем изменении очередная попытка будет в следующем цикле. Это одновременно резервная копия и регулярная активность репозитория. Проверять статус можно в Actions. [Документация GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## OpenAI для новостей

Используется уже заданный владельцем Actions secret `OPENAI_API_KEY`. Ключ не должен попадать в HTML, JavaScript, JSON сайта, логи или чат. Отключение генерации без удаления ключа: repository variable `OPENAI_NEWS_ENABLED=false`.

Модель — `gpt-6-luna`, Responses API со строгой JSON-схемой и `store:false`. Текст извлекается из открытой страницы через Trafilatura. Минимум исходного текста — 140 слов; пересказ обычно содержит 120–200 слов, для короткого источника — 75–110. Нельзя дописывать факты или общие советы ради длины. Результат проходит проверку структуры, объёма и длинных дословных совпадений. Автоматические тексты помечаются «AI-пересказ».

Лимиты: 6 платных запросов за запуск, 60 за день UTC; вход до 18 000 символов, выход до 2 200 токенов. Попытки учитываются до отправки. Временные ошибки получают время повторной проверки; после трёх ошибок API предусмотрен недельный перерыв. Изменившийся исходный текст можно обработать заново. Ограничения приложения не заменяют настройки бюджета API-проекта.

Счётчики и результаты хранятся в Actions cache `.cache/news-ai-cache.json`, готовые тексты также входят в опубликованный снимок. Полные оригиналы и ключи в кэш не записываются. При ошибке восстановления или повреждённом учёте платные вызовы пропускаются. GitHub cache может быть удалён, поэтому это не финансовая гарантия.

Обложки берутся из конкретной публикации на разрешённом домене. До шести готовых статей без изображения дополнительно проверяются за запуск даже при отключённом AI. Для новых пересказов фотография проверяется моделью одновременно с текстом — без отдельного платного запроса. Картинка скачивается только с разрешённых HTTPS-доменов издателя, ограничивается по размеру и отправляется как уменьшенное изображение. Зимний заголовок сам по себе не разрешает обложку: нужны подходящий верх и закрытая обувь. Неподходящая либо сомнительная фотография не публикуется. Проверка автоматическая и может ошибаться; человеческое одобрение не требуется для обычной публикации. Случайные общие кадры не подставляются. При недоступном изображении текст остаётся на нормальной ширине.

## Помощник на сайте

Проект Supabase: `renbakjudvdnkjvjujti`, функция `tonko-assistant`. Серверный секрет `OPENAI_API_KEY` задаётся в Supabase отдельно от GitHub Actions. В браузере используется только публичный publishable key.

Помощник не требует входа посетителя. История сохраняется в текущей вкладке и очищается кнопкой. Текущий вопрос и ограниченная история передаются через Supabase в OpenAI; собственная база не хранит тексты переписки. На сервере действуют лимиты 250 попыток в день для всего сайта и 24 в день для хеша адреса. Медицинские назначения, выдуманные цены и универсальные размерные таблицы не выдаются.

Справочник обновляется при каждой сборке сайта. Сервер получает новый снимок с Pages с интервалом кэширования 12 минут, при ошибке использует последний проверенный или встроенный. Подробности развёртывания, приватности, защиты от подмены ссылок и ограничения квот — [docs/ASSISTANT.md](docs/ASSISTANT.md).

Браузерные проверки используют Playwright и установленный Microsoft Edge: `qa/check-packaging.py`, `qa/check-news-layout.py`, `qa/check-news-queue.py`, `qa/check-assistant.py`. Последняя использует mock для воспроизводимых ошибок; реальная проверка OpenAI выполняется отдельно и не подменяется этим тестом. Для поддерживающих этот режим проверок опубликованного сайта задайте `TONKO_TEST_URL=https://big-arch.github.io/TOHKO/`.

GitHub Actions публикует только `tights-guide/`. Локальный кэш, серверный код, отчёты и секреты в сайт не включаются.

Каналы, даты и сортировка проверяются в `qa/check-video17.py`, свежесть статей и новостей — в `qa/check-news17.py`. Происхождение фотографий и логотипов доступно в `sources.html` и реестрах данных. Указание источника не является заявлением о свободной лицензии. Текстовый логотип ТОНКО сохранён по решению владельца.

Истории и фирменные фотографии для карточек упаковок хранятся в `tights-guide/data/brand-stories.json`. Сборка проверяет охват брендов, источники и локальные файлы, создаёт `brand-stories.js` и меняет версию ресурсов при обновлении содержимого. Браузерная проверка `python qa/check-package16.py` использует Playwright и Chrome; внешняя сеть во время неё заблокирована.

Избранное, место чтения и позиции видео сохраняются только в браузере устройства. Между устройствами они не синхронизируются. Снятая страница `fetish.html` оставлена нейтральной и с `noindex`; исключённые материалы не публикуются.
