## Локальный запуск

Из корня репозитория:

```sh
python -m http.server 4185 --directory tights-guide
```

Открыть http://localhost:4185/. Сайт использует готовые HTML, CSS, JavaScript и JSON, сборка npm не нужна.

## Структура

- `tights-guide/` — единственная публикуемая папка.
- `data/brands.js`, `data/brand-research.js` — каталог марок, модели, истории и проверенные источники.
- `data/photos.js`, `data/editorial-media.json` — галерея и происхождение редакционных фотографий.
- `data/packaging.json` — архив упаковок; `packaging.html/css/js` — фильтры, группы, увеличение и прямые ссылки.
- `data/news.json` — текущий снимок готовых статей и очереди; `news-sources.json` — разрешённые источники.
- `data/news-digests.json`, `data/news-illustrations.json` — проверенные тексты и фотографии, сохраняемые при автоматическом обновлении.
- `data/videos.json` — источники видео; `build-videos.py` создаёт страницу и поисковый индекс.
- `assistant.js/css`, `data/assistant-config.json` — интерфейс и публичные параметры помощника.
- `supabase/functions/tonko-assistant/` — сервер помощника, атомарные квоты и резервный справочник.
- `PRODUCT.md`, `DESIGN.md` — направление продукта и оформления; `qa/` — проверки.

Пути `data/…` выше относятся к `tights-guide/`, а builder-скрипты лежат в `scripts/`.

## Самостоятельное обновление новостей

Workflow [Publish TONKO](https://github.com/big-arch/TOHKO/actions/workflows/pages.yml) запускается после push в main, вручную и по расписанию в минуты 7, 22, 37 и 52 каждого часа. Он:

1. Проверяет код, загружает предыдущий опубликованный снимок и читает RSS/Atom подключённых источников.
2. Отбирает тематические публикации, убирает дубли и подтверждает прямую ссылку издателя, в том числе для обнаружений через Google News.
3. Получает открытый текст и готовит самостоятельный русский пересказ через OpenAI. Полные чужие статьи не перепечатываются; недоступные страницы и непроверенные ответы не превращаются в выдуманный текст.
4. Публикует готовые материалы, сохраняет очередь и счётчики повторов. При временной ошибке предыдущие статьи остаются доступными.
5. Пересобирает страницы и справочник помощника, затем публикует артефакт GitHub Pages.

Главная проверяет собственный снимок раз в минуту, пока вкладка видна. Новые материалы предлагаются кнопкой «Показать новые публикации», чтобы список не прыгал во время чтения. «Проверить ленту» перечитывает опубликованный файл, а не запускает внешний обход.

Ограничения архива: до 200 готовых материалов и отдельно до 200 обнаружений в очереди. Поток новых неподготовленных заголовков не вытесняет готовые статьи. Внешние источники и расписание GitHub не гарантируют мгновенную публикацию. Плановый запуск может задерживаться; в публичном репозитории GitHub отключает расписание после 60 дней без активности репозитория. Проверять статус можно в Actions. [Документация GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## OpenAI для новостей

Используется уже заданный владельцем Actions secret `OPENAI_API_KEY`. Ключ не должен попадать в HTML, JavaScript, JSON сайта, логи или чат. Отключение генерации без удаления ключа: repository variable `OPENAI_NEWS_ENABLED=false`.

Модель — `gpt-6-luna`, Responses API со строгой JSON-схемой и `store:false`. Текст извлекается из открытой страницы через Trafilatura. Минимум исходного текста — 140 слов; пересказ обычно содержит 120–200 слов, для короткого источника — 75–110. Нельзя дописывать факты или общие советы ради длины. Результат проходит проверку структуры, объёма и длинных дословных совпадений. Автоматические тексты помечаются «AI-пересказ».

Лимиты: 6 платных запросов за запуск, 60 за день UTC; вход до 18 000 символов, выход до 2 200 токенов. Попытки учитываются до отправки. Временные ошибки получают время повторной проверки; после трёх ошибок API предусмотрен недельный перерыв. Изменившийся исходный текст можно обработать заново. Ограничения приложения не заменяют настройки бюджета API-проекта.

Счётчики и результаты хранятся в Actions cache `.cache/news-ai-cache.json`, готовые тексты также входят в опубликованный снимок. Полные оригиналы и ключи в кэш не записываются. При ошибке восстановления или повреждённом учёте платные вызовы пропускаются. GitHub cache может быть удалён, поэтому это не финансовая гарантия.

Обложки берутся из конкретной публикации на разрешённом домене. До шести готовых статей без изображения дополнительно проверяются за запуск даже при отключённом AI. Для зимних тем автоматическая обложка требует редакционной проверки, чтобы летний образ не выдавался за зимний. Случайные общие кадры не подставляются. При недоступном изображении текст остаётся на нормальной ширине.

## Помощник на сайте

Проект Supabase: `renbakjudvdnkjvjujti`, функция `tonko-assistant`. Серверный секрет `OPENAI_API_KEY` задаётся в Supabase отдельно от GitHub Actions. В браузере используется только публичный publishable key.

Помощник не требует входа посетителя. История сохраняется в текущей вкладке и очищается кнопкой. Текущий вопрос и ограниченная история передаются через Supabase в OpenAI; собственная база не хранит тексты переписки. На сервере действуют лимиты 250 попыток в день для всего сайта и 24 в день для хеша адреса. Медицинские назначения, выдуманные цены и универсальные размерные таблицы не выдаются.

Справочник обновляется при каждой сборке сайта. Сервер получает новый снимок с Pages с интервалом кэширования 12 минут, при ошибке использует последний проверенный или встроенный. Подробности развёртывания, приватности, защиты от подмены ссылок и ограничения квот — [docs/ASSISTANT.md](docs/ASSISTANT.md).

## Сборка и проверка

После изменения редакционных исходников:

```sh
python scripts/build-editorial.py
python scripts/build-experience.py
python scripts/build-videos.py
python scripts/build-packaging.py
python scripts/build-home-news.py
python scripts/optimize-images.py
python scripts/build-assistant.py --inject
python scripts/check-site.py
```

`build-assistant.py --inject` запускается последним из HTML-builders. Он идемпотентен. Для оптимизации фотографий нужен Pillow; готовые WebP включены в репозиторий.

Проверки без внешней сети:

```sh
python -m unittest discover -s qa -p "test_news*.py"
python -m unittest qa/test_assistant_build.py
node --test qa/test_assistant.cjs qa/test_assistant_cache.cjs
node qa/test_video_memory.cjs
python scripts/check-site.py
```

Браузерные проверки используют Playwright и установленный Microsoft Edge: `qa/check-packaging.py`, `qa/check-news-layout.py`, `qa/check-news-queue.py`, `qa/check-assistant.py`. Последняя использует mock для воспроизводимых ошибок; реальная проверка OpenAI выполняется отдельно и не подменяется этим тестом. Для поддерживающих этот режим проверок опубликованного сайта задайте `TONKO_TEST_URL=https://big-arch.github.io/TOHKO/`.

GitHub Actions публикует только `tights-guide/`. Локальный кэш, серверный код, отчёты и секреты в сайт не включаются.
